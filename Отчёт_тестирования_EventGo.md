## Что мы сделали (общий итог)

**Документы.** Составили ТЗ проверки и доработки сайта на основе ТЗ хакатона EventTech (`ТЗ_проверки_и_доработки_EventGo.md`), провели тестирование и оформили этот отчёт, подготовили материалы к защите (`Защита_EventGo.md`: проблема, аудитория, архитектура, экономический эффект, план развития, сценарий показа).

**Исправленные дефекты.**

- Участник команды больше не получает контакты гостей и коды билетов (раньше код билета можно было использовать как чужой пропуск).
- Календарь открывается на текущем месяце.
- Организатор может отменить ошибочную отметку входа.
- Мелкие ошибки интерфейса: заголовок календаря, склонения, зашитые цифры на странице входа, предупреждение о перерасходе на обзоре, фильтр «Отменены».

**Новые возможности.**

- **Программа мероприятия:** секции, время, спикеры, залы; гости видят расписание на странице регистрации и в билете.
- **Управление гостями:** ручное добавление гостя и импорт списка из CSV/Excel с проверкой дублей и лимита мест.
- **Уведомления в кабинете (колокольчик):** просроченные задачи и задачи со сроком сегодня/завтра, новые регистрации, перерасход бюджета.
- **Опросы после мероприятия:** редактор вопросов (оценка, выбор, свободный ответ), ссылка на опрос в билете гостя, один ответ на билет, результаты с графиками и карточка в аналитике.

**Качество.** Для каждой доработки добавлены автотесты (сейчас 28 пройдено, 0 упало), всё проверено в браузере на временной копии базы, рабочие данные не затрагивались. Первая версия проекта выложена на GitHub: [TronTanya/EventGo](https://github.com/TronTanya/EventGo).

**Что осталось.** Конструктор формы регистрации, приглашения в команду с собственным аккаунтом, каталог площадок и подрядчиков, предупреждения о датах, автозавершение прошедших событий, почтовые рассылки.

## 1. Дефекты (то, что работает неправильно)

### D-1 · P1 · Участник команды видит персональные данные гостей и коды билетов — ✅ исправлено 25.10.2026

Сервер больше не отдаёт участнику `ticket`, `email`, `phone`, `consent_at`; в интерфейсе у участника скрыты колонки «Контакты» и «Билет». Добавлена проверка в автотест.

**Шаги:** войти как `team@eventgo.local`, запросить `GET /api/events/1`.  
**Факт:** в ответе полный список гостей: email, телефон, компания, время согласия и **секретный код билета** `ticket`. В интерфейсе участнику доступна кнопка «Билет» у каждого гостя.  
**Почему важно:** код билета работает как пропуск: по нему открывается билет с QR, и с ним можно пройти на вход вместо гостя. ТЗ (роль «участник оргкоманды») требует только «необходимую информацию о мероприятии».  
**Ожидание:** участнику отдавать имя, компанию и статус, без `ticket`, `email`, `phone` (или маскировать). Убрать кнопку «Билет» для роли `member`.  
**Где:** `server.mjs`, обработчик `GET /api/events/:id` (поле `guests`); `public/app.js`, `guestsView`.

### D-2 · P2 · Календарь открывается на ноябре 2026, а не на текущем месяце — ✅ исправлено 25.10.2026

**Факт:** в `public/app.js` месяц зашит: `month:'2026-11'`. Сегодня 25 октября, и просроченные октябрьские задачи («Согласовать площадку», срок 22.10) в календаре по умолчанию не видны.  
**Ожидание:** при открытии показывать текущий месяц (`today().slice(0,7)`).

### D-3 · P2 · Ошибочную отметку входа нельзя отменить — ✅ исправлено 25.10.2026

Организатор выбирает у пришедшего гостя другой статус, подтверждает действие; отметка входа снимается, в ленте появляется запись. Сценарий добавлен в автотест.

**Шаги:** отметить вход гостя, попытаться вернуть статус «Подтверждён».  
**Факт:** `409 Гость уже прошёл регистрацию на входе.` Отменить не может даже организатор.  
**Ожидание:** организатор может снять отметку входа (с записью в ленту действий).

### D-4 · P2 · Нет проверки дат

- Событие можно создать с датой в прошлом (проверено: 2020-01-01 создалось).
- Задачу можно поставить со сроком **после** даты мероприятия (проверено: 2027-05-01 при событии 2026-12-01).

**Ожидание:** предупреждение (не обязательно запрет) в обоих случаях.

### D-5 · P3 · Статус события не меняется сам

Прошедшее событие остаётся «В подготовке» или «Идёт сейчас», пока организатор не сменит статус вручную. Из-за этого прошедшие события продолжают висеть в афише.  
**Ожидание:** подсказка «Событие прошло — завершить?» или автоматический переход в «Завершено».

### D-6 · P3 · Мелкие ошибки интерфейса — ✅ частично исправлено 25.10.2026

Исправлены: «Г.» в календаре, склонение «подрядчик», зашитые цифры на странице входа, предупреждение о перерасходе на дашборде, фильтр «Отменённые». Остались: название команды в меню и молчаливое игнорирование `owner_id`.

| Где | Ошибка |
| --- | --- |
| Календарь, заголовок | «Ноябрь 2026 Г.»: CSS делает «г.» заглавной |
| Обзор, блок «Команда события» | «… · 1 подрядчик»: слово не склоняется (2 подрядчик, 5 подрядчик) |
| Страница входа | Цифры «12 задач / 48 регистраций / 350 тыс.» зашиты в коде и не меняются с данными |
| Боковое меню | «Команда «Не по ТЗ»» зашито, не настраивается |
| Ответ `PATCH /api/events/:id` с `owner_id` | Возвращает `200 ok`, но ничего не меняет: молча игнорирует поле |
| Перерасход бюджета | Предупреждение только в разделе «Бюджет», на дашборде его нет |
| Список гостей | Нет фильтра «Отменённые» |

## 5. Что работает хорошо (повторно не трогать)

- Весь демо-сценарий ТЗ: создание события, задачи, ответственные, сроки, регистрация, бюджет, показатели.
- Права доступа к финансам: участник не получает бюджет, расходы, стоимость подрядчиков и отчёт (проверено через API).
- Регистрация: лимит мест, запрет повторного email без учёта регистра, обязательное согласие.
- Check-in: отклоняет повторный вход, отменённые и чужие билеты.
- Канбан, комментарии, вложения, чат, ИИ-ассистент, CSV, JSON-отчёт, резервная копия базы.
- Данные сохраняются после перезапуска; автотесты проходят.
