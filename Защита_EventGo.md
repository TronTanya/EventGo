# EventGo — материалы к защите

Документ для презентации прототипа: проблема, аудитория, что сделано, архитектура, экономический эффект и план развития.

---

## 1. Проблема

Подготовка мероприятия обычно размазана по нескольким инструментам:

- задачи и дедлайны — в таблицах и чатах;
- состав команды и подрядчики — в переписке;
- бюджет — в отдельной таблице;
- регистрация гостей — на стороннем сервисе;
- контроль входа — по бумажным спискам или Excel.

Из-за этого организатор тратит время на сверку данных, ошибается в списках и поздно замечает просроченные задачи или перерасход. Гостю неудобно: регистрация отдельно, билет отдельно, программа — ещё где-то.

**EventGo** собирает эти процессы в одном локальном рабочем пространстве: событие → задачи → команда → гости → бюджет → вход по QR → обратная связь.

## 2. Целевая аудитория

| Кто | Как работает в EventGo |
| --- | --- |
| Организатор форума, хакатона, встречи | Полный кабинет: события, задачи, гости, бюджет, аналитика, опросы |
| Участник оргкоманды | Свои задачи, файлы, чат; без финансов и аналитики |
| Гость | Афиша, регистрация, билет с QR, программа, опрос после события |
| Ивент-команда / учебный проект | Демо-аккаунты, запуск без установки СУБД и облака |

## 3. Что умеет прототип сейчас

### Обязательный сценарий хакатона

1. Создать мероприятие (дата, место, вместимость, бюджет).
2. Собрать команду и назначить задачи со сроками.
3. Открыть регистрацию, принять гостя, выдать билет `EG:…` с QR.
4. Отметить вход на площадке.
5. Вести бюджет и смотреть готовность / аналитику.
6. Данные сохраняются после перезапуска.

### Усиления относительно базового MVP

| Модуль | Зачем организатору |
| --- | --- |
| Программа события | Гости видят расписание на странице регистрации и в билете |
| Ручное добавление и импорт CSV | Быстро загрузить список из Excel / почты партнёров |
| Уведомления в кабинете | Просроченные задачи, новые регистрации, перерасход бюджета |
| Опрос после мероприятия | Оценка и комментарии гостей → сводка в аналитике |
| Чат команды и ИИ-ассистент | Координация и подсказки без ухода в мессенджер |
| Афиша и «Мои билеты» | Публичный вход для гостей без аккаунта |

Демо-вход: `organizer@eventgo.local` / `EventGo2026!`, участник команды: `team@eventgo.local` / `TeamGo2026!`.

## 4. Архитектура

```text
START.cmd / runtime/node.exe
        │
        ▼
   server.mjs  ── HTTP API, сессии, права, check-in, backup
        │
   ┌────┴────────────┐
   ▼                 ▼
 db.mjs            public/
   │               SPA (app.js, style.css, qr.js, chat, AI)
   ├── DATABASE_URL задан → pg-adapter.mjs → PostgreSQL 16 (основная база)
   └── не задан          → SQLite data/eventgo.sqlite (запасной режим)
 data/uploads/  загруженные файлы
```

| Решение | Почему |
| --- | --- |
| Node.js 24, PostgreSQL 16 | Основная база для многопользовательской работы и развёртывания |
| Docker Compose (`db` + `web`) | Сайт с базой поднимается одной командой |
| Запасной SQLite (`node:sqlite`) | Запуск двойным щелчком без установки сервера БД |
| Один исполняемый runtime в папке | Запуск на Windows без установки Node.js |
| Роли на сервере | Участник команды не получает бюджет даже прямым API-запросом |
| Автотесты `tests/` | Регрессии по ролям, гостям, файлам, опросам |

## 5. Экономический эффект

Оценка для типичного делового события на **150–200 гостей** и команды из **5–8 человек** (форум / хакатон / корпоративная встреча). Цифры ориентировочные: для сравнения «как сейчас» и «с EventGo», не как гарантия экономии.

### 5.1. Где теряется время сегодня

| Операция | Без единой системы | С EventGo | Экономия на одно событие |
| --- | --- | --- | --- |
| Сбор списка гостей из форм, почты, чатов | 4–6 ч | Импорт CSV + ручное добавление: 0,5–1 ч | **≈ 4 ч** |
| Сверка дублей и статусов «пришёл / нет» | 2–3 ч | Статусы и check-in по QR | **≈ 2 ч** |
| Координация задач (чат + таблица) | 3–5 ч в неделю подготовки | Дашборд + уведомления о сроках | **≈ 3 ч** |
| Сбор обратной связи после события | 2–4 ч (отдельная форма + сводка) | Опрос в билете → готовая аналитика | **≈ 2 ч** |
| Отчёт для руководства / партнёров | 2–3 ч | JSON/CSV-экспорт + экран аналитики | **≈ 1,5 ч** |

**Итого: порядка 12–13 часов** координационной работы на одно событие.

При ставке координатора **800–1200 ₽/час** это **≈ 10–15 тыс. ₽** прямых трудозатрат на событие. Для агентства с **10 событиями в месяц** — **≈ 100–150 тыс. ₽** в месяц времени, которое можно вернуть в продажу и качество площадки, а не в «сверку таблиц».

### 5.2. Качественный эффект (не только часы)

- Меньше ошибок на входе: повторный check-in блокируется, отменённый билет не проходит.
- Меньше утечек контактов: участник команды не видит почту и телефон гостей.
- Быстрее реакция: колокольчик показывает просрочки и новые регистрации без открытия Excel.
- Понятный ROI мероприятия: средняя оценка опроса и стоимость на гостя видны в аналитике сразу после события.

### 5.3. Масштаб

| Горизонт | Что даёт продукт |
| --- | --- |
| Хакатон / пилот | Один ноутбук, демо-данные, полный сценарий за минуты |
| Команда города / вуза | Несколько событий в одной базе, общая методология |
| Агентство | Тиражирование процесса: шаблон события → импорт гостей → QR → опрос |

## 6. План развития

### Ближайший контур (усиление текущего прототипа)

| Направление | Содержание |
| --- | --- |
| Форма регистрации | Конструктор полей под тип события |
| Команда | Приглашения по ссылке, без ручного ввода email |
| Площадки | Каталог площадок и подрядчиков с поиском |
| Напоминания | Email / мессенджер о сроках задач и открытии регистрации |
| Качество данных | Предупреждения о пересечении дат, автозавершение прошедших событий |

### Продуктовый контур

| Направление | Содержание |
| --- | --- |
| Аккаунты | Регистрация организаторов, организации (мультитенантность) |
| Доставка | Реальная отправка билетов и опросов на почту |
| Хостинг | HTTPS, резервные копии по расписанию, обновления |
| Календарь | Синхронизация с Google / Outlook |
| Аналитика | Сравнение нескольких событий, NPS, повторные гости |

Принцип развития тот же, что в ТЗ хакатона: сначала закрывать реальные боли организатора, потом наращивать «облачные» возможности.

## 7. Сценарий демонстрации (2–4 минуты)

1. Запуск `START.cmd` → вход организатором.
2. Открыть **IT-Форум 2026**: обзор готовности, программа, гости.
3. Показать **уведомления** (сроки / регистрации).
4. Скопировать ссылку регистрации → зарегистрировать тестового гостя → показать билет и QR.
5. **Проверить билет** на входе.
6. Раздел **Опрос гостей** (хакатон): средняя оценка, распределение ответов, ссылка в билете.
7. **Аналитика**: посещаемость, расход на гостя, карточка опроса.
8. Вход участником команды: задачи есть, бюджета нет.
